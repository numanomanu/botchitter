# botchitter — 一人Twitter

> **「今を観る。点を残す。いつか、線になる。」**  
> 思考のログを淡々と残し、過去の自分と対話するための、完全ローカル完結型「一人Twitter」PWA。

---

## 1. コンセプト・背景（そもそも何を作ろうとしていたのか）

### 逆転した時間観：未来 → 現在 → 過去
一般的には時間は「過去 → 現在 → 未来」へ流れていると考えられます。  
しかし、このプロダクトの根底には**「時間は未来から現在、そして過去へと流れているのではないか」**という時間観があります。

- **未来**には、世界や自分自身の大きな流れがすでに兆候として存在している。
- **現在**において、人間はその流れの中で目の前に現れる小さな選択肢を選びながら生きている。
- **過去**は出来事そのものは変えられなくても、その「意味」は現在からいくらでも変えられる（「あの時の失敗が、すべての始まりだった」と思えるように）。

### 「未来を見る」とは何か
ここでいう「未来を見る」とは、オカルトや未来予知のことではありません。  
未来からの流れが現在に向かっているのなら、その兆候はすでに**「今」の中に小さな違和感・興味・変化**として現れているはずです。

- 最近、妙にあることばかり考えてしまう
- 特定の人の言葉だけがなぜか耳に残っている
- 今まで好きだったものへの関心が薄れ、別の何かに惹かれている
- 日常や仕事の現場で小さな変化を感じる

その瞬間には何の意味があるのか分かりません。  
しかし半年後、1年後に振り返ったとき、「あの時点ですでに始まっていたんだ」と気づくことがあります。

### 「意味のない点」を残す
このアプリにおける記録は、普通の日記や目標管理ではありません。  
今という時間の中に見つけた**「点」**をただ残すこと。

記録する時点で「何のために」「どういう意味があるか」をアプリ側で分類させたり、解釈させたりしません。  
「ただ、点を置く」。それだけで十分です。

### 点と点がつながり、線になる（過去の自分との再会）
このアプリの主役は、書く瞬間以上に**「過去の自分と再会する瞬間」**です。  
時間が経ち、過去の記録を見返したとき、あるいは過去の投稿を引用したとき、初めてバラバラだった点が一本の線になります。

> **点 → 点 → 線**  
> 過去の自分が見ていた未来に、あとから出会う。

## 2. なぜ「一人Twitter」という形に行き着いたのか

開発当初は「予感日記」や問いかけ型のメモアプリをプロトタイプとして作成していましたが、検証を重ねる中で以下の課題と本質が見えてきました。

1. **詩的すぎるUI・説明過多なUIの違和感**  
   「今日、何が見えた？」「線になる」といった詩的な言葉や、「タップしていつでも書き直せます」といった説明が必要なUIは、思考の邪魔になり入力する気を失わせる。  
   アプリは徹底して淡々としており、日常の道具として静かであるべき。

2. **過去のメモを「編集」してはいけない**  
   過去の思考を上書き編集してしまうと、「あの時どう感じていたか」という定点観測が消えてしまう。  
   Twitterのように「投稿する」「削除する」「コメントする」「引用する」という制約があるからこそ、思考のログが歪まずに残る。

3. **「引用リツイート」によって過去を現在へ引き上げる**  
   過去の投稿に対してただコメントするだけでなく、**「引用」することで過去の点を現在のタイムライン最前線に浮上させる**。  
   「過去にこんなことを言っていたが、今の自分から見るとこう解釈できる」という、まさに*過去の意味を現在から更新する行為*が、Twitterの引用リツイートUIと完璧に一致した。

4. **誰も見ない、完全なプライベート空間**  
   他人の反応や「いいね」を気にするSNSでは、本当の思考や未整理の兆候は書けない。  
   サーバー通信を行わず、端末内のローカルストレージ（IndexedDB）にのみ静かに保存される「一人だけの閉じたTwitter」だからこそ、自分自身と純粋に対話できる。

## 3. UI/UX の設計原則

- **言葉を削ぎ落としたミニマルなUI（ノンバーバルUI）**  
  ボタンの「コメント」「引用」「シェア」などの文字ラベルを排除し、アイコンと余白だけで直感的に伝わる洗練されたUI。
- **10秒で開いて残せる静けさとスピード**  
  タグ付け、重要度、カテゴリ分類などの作業をユーザーに強要しない。余計な思考コストを奪わず、思いついた瞬間に書き込める。
- **AIやシステムによる決めつけをしない余白**  
  「あなたの思考傾向」などの分析やスコアリングをアプリ側が押し付けない。気づくための余白をユーザー自身に残す。
- **能動的なシェア**  
  基本的にデータは端末外に出ないが、外の世界に発信したくなった瞬間だけ、ユーザー自身の意思で任意のSNS（X等）へシェアできる。

## 4. 主な機能

- **一人タイムライン**: 思考の点を時系列でストック。
- **コメント（スレッド）**: 一つの投稿から思考をさらに深掘り・追記。
- **引用ポスト（Quote）**: 過去の投稿やコメントを現在の最新思考としてタイムライン最前線に引き上げ。
- **リンク**: 本文中の URL はタップで開ける。URL 付きで投稿すると、そのページのタイトルとサイト名をカードで表示する。
- **タグ**: 本文に `#株` のように書くとタグになり、タップでそのタグのポスト（コメントにタグがあるものも含む）に絞り込める。入力中もタグはハイライトされる。絞り込み中は入力欄の先頭にそのタグが自動で入るので、そのまま書けばそのタグのポストになる（消せば普通のポスト）。タグの一覧と件数は右上のメニューから。
- **編集**: 詳細ビューからだけ、ポストとコメントを編集できる。前の版は消えずに履歴として残り、詳細ビューでたたんで見られる。
- **パーマリンク & 詳細ビュー**: 各ポストが固有リンク（`#tweet-id`）を持ち、引用元や未来の引用ポストとの関係性を可視化。
- **完全ローカル保存**: 端末内の IndexedDB に保存（IndexedDB が使えない環境向けに LocalStorage にも控えを置く）。
  例外として、URL 付きで投稿・編集した時だけ、その URL（本文は送らない）を自前の API（`api/ogp.js`）に送ってタイトルを1回取得し、結果を投稿と一緒に保存する。
- **バックアップ**: 右上のメニューから JSON で書き出し・読み込み。読み込みは ID 単位のマージなので、既存の記録は上書きされない。
- **能動的SNSシェア**: Web Share API および X Intent 連携。
- **PWA（Progressive Web App）完全対応**: ホーム画面に追加することで、URLバーなしの全画面ネイティブアプリとしてオフライン利用可能。
- **ダークモード & 端末セーフエリア対応**: Dynamic Island やノッチに配慮した快適なフルスクリーン表示。

### iPhone で使うときの注意
Safari のタブのままだと、7日間開かなかったサイトのデータは消されることがあるため、**ホーム画面に追加して使う**（Safari で開くと案内が出る）。
Safari とホーム画面版は保存領域が別なので、Safari で書いた記録を移すにはバックアップの書き出し → 読み込みを使う。

## 5. ファイル構成

- `index.html`: セマンティックマークアップ、PWAメタ設定
- `style.css`: ミニマルデザイン、セーフエリア・フォント設定、アニメーション
- `data.js`: 保存キー、初期シードデータ
- `app.js`: アプリケーションロジック（言語リソース、IndexedDB、描画、ルーティング、バックアップ）。データ構造は冒頭のコメント
- `sw.js`: オフラインキャッシュ用 Service Worker（ネットワーク優先）
- `api/ogp.js`: リンクのタイトル取得 API（Vercel Function）
- `manifest.json`: PWAマニフェスト

ビルド不要・依存なし。開発時は `python3 -m http.server 5173` で `http://localhost:5173` を開く（`file://` では動かない）。
